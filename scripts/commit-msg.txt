fix: a malformed request body is a 400, not a 500

`req.json()` rejects a malformed body with a SyntaxError, and the API
wrapper only knew about ApiError and ZodError - so a broken request fell
through to the internal-error branch and came back as HTTP 500. A client
that sent broken JSON was told the server had crashed.

handleApi now recognises a JSON parse error and answers 400 with
INVALID_JSON. The matcher is deliberately loose about the wording, because
Node says "Expected property name or '}' in JSON at position 1" while
browsers and other runtimes say "Unexpected token ...".

tests/unit/http.test.ts covers it, and scripts/check-input-validation.cjs
checks it against a running instance: sixteen malformed requests across the
auth, contact, campaign, template, segment, service and task endpoints all
have to be a 4xx - never a 5xx.

The same script also confirmed something worth knowing: the endpoints that
require a session answer 401 before they validate, so an unauthenticated
caller cannot probe the schema. That is the intended order.

node scripts/validate-all.mjs now runs the input-validation checks too.
