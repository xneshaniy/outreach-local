docs: record the deployment blocker and what was hardened for production

docs/GO-LIVE.md now records the Hostinger MCP situation precisely: what was
tried (the API token as a bearer header, as a raw header, as X-Api-Key, as a
query parameter, and the Hostinger REST API), what each returned, and the
server's own www-authenticate header, which shows it wants OAuth 2.1 with
Dynamic Client Registration at auth.hostinger.com with the mcp:use scope.

So the deployment needs one authorisation step by the account owner: /mcps,
select hostinger, sign in. The alternative - a redeploy from the panel with
.env.hostinger imported - is documented too.

The runbook also records the three things that were hardened for production:
a retried claim can no longer take more than its batch limit, contended
transactions have room to finish instead of hitting Prisma's 5-second
timeout, and nothing that can be used as a credential reaches the log.
