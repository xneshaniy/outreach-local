test: add the production-safety checks to the validation suite

scripts/production-safety-check.cjs starts the built bundle with DRY_RUN=true
and asserts the things that must not be able to go wrong in production:

  - the health endpoint answers and reports the database up
  - an unauthenticated admin API is rejected (dashboard, contacts, campaigns)
  - a forged tracking token records no event, the open pixel still answers
    with a GIF, and a forged click is rejected without redirecting
  - a forged unsubscribe token is rejected
  - a cross-origin write is rejected by the CSRF guard
  - the dry run never contacted a provider
  - the sender worker started
  - no credential appears in the log

Two of these initially failed and both were the assertion being wrong, not the
code. The tracking pixel answers 200 with a 1x1 GIF even for a forged token
on purpose - a broken image in someone's inbox is worse than a missed
statistic - so what matters is that no event is recorded. And a forged click
answers 400 rather than redirecting, because the target URL only ever comes
from the signed token, so a forged link must not be able to bounce anyone
anywhere.

node scripts/validate-all.mjs now runs them.
